# v0.4.4 -- ComfyUI cache policy: paused workflows survive other workflows

Hand-run checks for the startup cache override shipped in Dazzle Command v0.2.9-alpha and Preview Bridge Extended v0.4.4-alpha. The unit tests (`tests/test_cache_policy.py`) cover every decision branch with injected values; these steps cover what they can't: the real ComfyUI load order, the real cache, and real renders.

## Prerequisites

- ComfyUI with the RAM-pressure cache (startup log says `Using RAM pressure cache.`), on a machine with 32-128 GB of RAM
- A two-stage workflow gated by Dazzle Command (or a Preview Bridge Extended block), with a slow first stage, plus any second, different workflow
- Launch with `--verbose DETAIL` so each sampler that actually runs logs a `Sampler: model=...` line

## 1. Fix active on a plain launch

- [ ] Start ComfyUI **without** `--cache-ram`.
- [ ] Startup console shows one line like `[DazzleCommand] ComfyUI cache: keeping other workflows' cached results until free RAM < 25.4 GB (equivalent to --cache-ram 10 25.4).` (values scale with your RAM: 20% of total, never below the first value).
- [ ] That line appears **before** `Using RAM pressure cache.`
- [ ] Gated workflow: Pause, run. The first stage's sampler runs.
- [ ] Other workflow: run it once.
- [ ] Gated workflow: Play, run. **The first stage's sampler does not appear** in the log; only stages after the gate run. No duplicate output files from the first stage.

## 2. Control arm: opt-out restores ComfyUI's behavior

- [ ] Set `DAZZLE_CACHE_RAM_OVERRIDE=0` and restart.
- [ ] Startup line reads `ComfyUI cache: disabled by DAZZLE_CACHE_RAM_OVERRIDE=0 -- using ComfyUI's cache defaults.`
- [ ] Repeat the three runs from section 1. **The first stage renders again** on Play, with the same seed as the paused run.
- [ ] Clear the variable afterwards.

## 3. Explicit settings win

- [ ] Restart with `--cache-ram 10 32`. Startup line says it is respecting your cache choice.
- [ ] Restart with `--cache-classic`. Same.
- [ ] Restart with a single `--cache-ram 5`. Startup line names `--cache-ram 5 ...` with your 5 kept.

## 4. Applied once

- [ ] With both Dazzle Command and Preview Bridge Extended installed, only **one** `ComfyUI cache:` line appears at startup.

## What the unit tests don't cover

- Whether ComfyUI still loads custom nodes before the prompt worker reads its cache settings (section 1, line order).
- Whether the cache actually keeps the paused workflow's results (sections 1 and 2).
- Console wording as a user sees it.
